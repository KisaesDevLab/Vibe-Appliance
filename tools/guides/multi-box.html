1. The shape of a multi-box firm

Some firms outgrow one server: an appliance box (or several) running the accounting apps, and a separate box running Vibe Sentinel — the security-monitoring and compliance stack, which wants its own hardware (4 cores / 8 GB free for its core alone). This guide covers the part that trips people up: connecting the other machines to Sentinel so it actually watches them.

Two layers connect every machine, always in this order:

  1. The mesh (NetBird). A private WireGuard network between the firm's machines. Every Sentinel service listens only on the mesh interface.
  2. The monitoring agent (Wazuh). Installed on each machine, reporting to the Sentinel box over the mesh.

2. "But my boxes are on the same network — do I need the mesh?"

Yes — and not because of routing. Three reasons, and one reassurance:

  • Sentinel doesn't listen on your LAN, on purpose. Its services bind the mesh interface only. An office LAN has printers, phones, guest Wi-Fi, and whatever a visitor plugged in; "on the LAN" is not an identity.
  • The mesh is the identity layer. A mesh peer enrolled with a one-time key is a known machine with its own cryptographic identity — that is what the monitoring evidence hangs off.
  • It's the encryption layer, and it travels. Agent traffic is encrypted end-to-end (WireGuard), and the same enrollment keeps working when a laptop goes home for the weekend.
  • The reassurance: two mesh peers on the same LAN connect directly to each other — no relay, no round-trip through the internet. On one network the mesh costs approximately nothing and you keep all three properties above.

A firm that already runs an equivalent overlay (Tailscale, for example) can leave Sentinel's mesh module off — that is a Security Six control, so the installer records the compensating control you name. That's the sanctioned path; binding Sentinel's services to the bare LAN is not.

3. Connect another appliance box (from its own console)

On each additional appliance/app box, the admin console does this for you:

  1. On the Sentinel box, generate enrollment credentials: 
    sudo bash /opt/vibe-sentinel-installer/lite/generate-lite.sh --platform linux --role docker-host
    The output includes the four values the next step asks for: the NetBird management URL, a one-time setup key (single-use, expires in 48 hours — generate it when you're ready), the Wazuh manager's mesh hostname, and the agent-enrollment password.
  2. On the app box's console: Apps → the Security & Compliance section → Connect this box to the firm's Sentinel… Paste the four values, pick the role (docker-host for an appliance), click Connect. The box joins the mesh first, health-checks it, then installs and enrolls the agent — the transcript streams into the page, and every failure names the step and the fix. Re-running is safe; it converges.
  3. Verify: the box's Host services panel shows Sentinel enrollment — enrolled, and the machine appears in the Wazuh dashboard on the Sentinel box within a couple of minutes.

4. Connect workstations and other machines

Staff computers use the same generator with per-platform bundles:

sudo bash /opt/vibe-sentinel-installer/lite/generate-lite.sh --platform all --role workstation

That produces Windows, macOS, and Linux bundles under /var/lib/vibe-sentinel/lite/<timestamp>/, each carrying the mesh client with its one-time key, the preconfigured agent, the audit rules for its platform, and a posture collector — run the bundle on the machine and it enrolls itself, mesh first, refusing to continue if the mesh doesn't come up. Bundles contain credentials: move them on encrypted media or over the mesh, never by email, and delete them once the batch is enrolled. One key per machine.

5. What else connects across boxes

  • Uptime monitoring: Sentinel's pulse module (Uptime Kuma) can probe each appliance box's /health endpoints across the mesh — add the monitors in Sentinel's own UI.
  • One print gateway, firm-wide: Vibe Print and Sentinel's print module are the same product (the cards say so). In a multi-box firm, run Sentinel's copy and leave the appliance boxes' copies disabled — the apps reach it over the mesh, and one gateway means one job history and one audit log.
  • The catalogs link up: each appliance console lists the Sentinel modules and links to the Sentinel host's UI once it answers on the firm domain — one place to see the estate from any box.

6. If something goes wrong

  • Mesh joined but the agent won't confirm: almost always the wrong manager hostname, a wrong enrollment password, or 1514/1515 closed on the Sentinel host's mesh interface. The Connect transcript's last step says which; fix and re-run — it converges.
  • "Setup key rejected": keys are one-time and short-lived by design. Generate a fresh one on the Sentinel box and try again.
  • A box stops reporting: check its Host services panel (Sentinel enrollment row), then sudo netbird status and sudo systemctl status wazuh-agent on that box. The Sentinel side alerts on silent agents — that is its job.
