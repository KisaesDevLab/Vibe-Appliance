1. What you are setting up

The Vibe Appliance is a single Linux server that runs your firm's Vibe stack — Trial Balance, MyBooks, Connect, Tax-Research, Payroll & Time, Practice Management, and the rest — plus the supporting infrastructure (database, cache, TLS, backup, monitoring). One install. One server. No fleet.

You need to be able to copy a command into a terminal and to know your firm's domain name. You do not need to have used Docker before. Day-to-day operation after the install happens entirely in a browser.

The design promise: every step can be re-run safely. If an install fails halfway, fix the thing the error message names and run the same command again — it picks up where it stopped. Every error the appliance prints includes a recovery hint.

Domain + Tailscale can run together: public for clients, tailnet-only for staff admin. In every mode, all apps share one hostname with a path per app — e.g. https://vibe.firm.com/tb/, http://<host>.local/mybooks/. Enabling more apps never creates DNS work.

3. The quickest path (domain + Cloudflare Tunnel)

Recommended for most firms: no router changes, no port forwarding, real TLS handled by Cloudflare. Seven steps, about 30 minutes including account setup.

  1. Create an Ubuntu 24.04 droplet at DigitalOcean. Recommended size s-2vcpu-4gb ($24/mo) — runs every app with headroom. (s-1vcpu-2gb works for two or three apps.) Note its public IP.
  2. SSH in: ssh root@<droplet-ip>. On Windows, PowerShell's built-in ssh works.
  3. Create a Cloudflare API token (your domain's DNS must be on Cloudflare — free, and your registrar doesn't change). Profile → API Tokens → Create Token → Custom token, with permissions Account → Cloudflare Tunnel → Edit and Zone → DNS → Edit on your zone. Copy it immediately — Cloudflare shows it once.
  4. Run the installer on the droplet, replacing the two placeholder values: 
    curl -fsSL https://raw.githubusercontent.com/KisaesDevLab/Vibe-Appliance/main/bootstrap.sh \
  | sudo bash -s -- \
    --mode domain \
    --domain firm.com \
    --tunnel-subdomain vibe \
    --email admin@firm.com
    It runs eight numbered phases over 5–15 minutes, then prints your console URL and admin password. Copy the password now — it also lives in /opt/vibe/CREDENTIALS.txt on the server.
  5. Open the admin console at https://<droplet-ip>/admin. Your browser warns about a self-signed certificate — that's expected before the tunnel exists; click through. Username admin, paste the password.
  6. Provision the Cloudflare Tunnel: in the console, Configuration → Network → Cloudflare Tunnel. Paste the API token, let the wizard discover your account and zone, click Use these values, Save, then Provision tunnel now. About 30 seconds later the appliance is live at https://vibe.firm.com/ with real TLS.
  7. Enable your first app — see §6 below.

4. The other install commands

Same installer, different flags. Run on the server as root.

LAN mode (the default — no flags)

curl -fsSL https://raw.githubusercontent.com/KisaesDevLab/Vibe-Appliance/main/bootstrap.sh | sudo bash

Tailscale mode

Generate an authkey at login.tailscale.com → Settings → Keys, then:

curl -fsSL https://raw.githubusercontent.com/KisaesDevLab/Vibe-Appliance/main/bootstrap.sh | sudo bash -s -- \
  --mode tailscale \
  --tailscale-authkey tskey-auth-XXXXXX

Domain mode with your own port forwarding (no tunnel)

If you can forward ports 80/443 to the server, add one DNS A record (vibe.firm.com → server IP) and run the domain-mode command from §3 step 4; certificates are issued automatically on the first request. Cloudflare DNS-01, Namecheap DNS-01 and Namecheap Dynamic DNS variants are covered in docs/INSTALL.md §2.

If a phase fails: don't re-run blindly. Read the message — it names what failed, the common causes, a diagnose command and a fix. Fix that one thing, then run the same install command again. Re-running is safe and it converges.

5. Your credentials

Everything you need is in one root-only file on the server:

sudo cat /opt/vibe/CREDENTIALS.txt
  • Console URL — domain mode https://vibe.firm.com/admin; LAN http://<server-ip>/admin; Tailscale https://<host>.<tailnet>.ts.net/admin.
  • Username admin and the 64-character password — paste it, don't type it.
  • The Duplicati backup passphrase — see §7; losing it makes backups unrecoverable.

Store the password and the backup passphrase in your firm's password manager now.

6. Enable apps

  1. In the admin console, scroll to Apps. Each Vibe app has a card.
  2. Click Enable — Vibe Trial Balance is the recommended first app.
  3. Within ~2 minutes the badge goes not-installed → enabling… → running, and the card shows the live URL. No DNS work is ever needed for a new app.
  4. Open the URL, sign in with the credentials from the console's First-login info panel, and set a real password when prompted.

Each app card links its own setup guide (PDF) — enabling steps, where to sign in, and the settings that particular app needs.

7. Set up backups before real work

Do this before trusting the appliance with client data. In the console → Infra services → Duplicati (backup) (reachable from the LAN or Tailscale only — never exposed publicly):

  1. Set Duplicati's web password.
  2. Add a backup: source paths /source/vibe-data and /source/vibe-env are already mounted read-only.
  3. Destination: an off-site target you own — S3-compatible storage, Backblaze B2, or rsync.net. Don't leave it unset.
  4. Encryption passphrase: the DUPLICATI_PASSPHRASE value from /opt/vibe/CREDENTIALS.txt. If you lose this passphrase, your backups are unrecoverable.
  5. Schedule nightly. Run one backup manually, then test restoring a single file to a scratch path so you know the recovery path works.

9. When something breaks

  • sudo vibe doctor is the single best first move. It checks the host, the core services, every enabled app, DNS and certificates, and prints exactly which check failed and what to do.
  • Every error message follows the same shape: what failed → common causes → a diagnose command → a fix command → the next step. Do what it says, in order.
  • Re-running the installer is always safe. It repairs a half-finished state rather than damaging a good one.
  • docs/TROUBLESHOOTING.md in the appliance repository is keyed by symptom, from "console doesn't load" up.
  • Disaster path: with your Duplicati backup and its passphrase, a fresh server plus the same install command plus a restore of /opt/vibe/data and /opt/vibe/env brings everything back.
